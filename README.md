# Описание проекта 
  Это небольшой проект, который генерирует и анализирует CSV-данные с помощью разных Docker-контейнеров. 
  В проекте есть 2 основные сущности, а именно генератор данных и аналитик данных. Теперь подробней о каждом. Генератор данных, это скрипт который создает CSV файл data.csv с данными. Я выбрала тему путешествий. Аналитик данных- это другой скрипт, который уже читает файл CSV и создает HTML отчет report.html
  Обе сущности запускаются в отдельных Docker-контейнерах, но работают с общей локальной папкой data/ которая располагается на хосте.

## 3. Основной скрипт run.sh

В проекте реализован основной bash-скрипт run.sh. Он нужен для запуска всех основных команд проекта из одного места.
---1--Команда ./run.sh build_generator собирает Docker-образ генератора данных.
--2--Команда ./run.sh run_generator запускает контейнер генератора и создает файл data/data.csv.
--3--Команда ./run.sh create_local_data запускает генератор локально, без Docker, и создает файл local_data/data.csv. Эта команда нужна для локальной отладки генератора.
--4--Команда ./run.sh build_reporter собирает Docker образ аналитика данных.
--5--Команда ./run.sh run_reporter запускает контейнер аналитика, читает файл data/data.csv и создает HTML отчет data/report.html.
--6--Команда ./run.sh structure выводит структуру всех файлов и директорий проекта, начиная с текущей папки.
--7--Команда ./run.sh clear_data удаляет файлы .csv и .html из папки data/. После выполнения этой команды папка data/ остается, но результаты работы программы удаляются.
--8--Команда ./run.sh inside_generator запускает контейнер генератора и показывает содержимое папки /data внутри контейнера. Так можно проверить, что контейнер видит данные, которые лежат на хосте.
--9--Команда ./run.sh inside_reporter запускает контейнер аналитика и показывает содержимое папки /data внутри контейнера. Эта команда нужна для проверки того, что reporter-контейнер видит файлы из локальной папки data/.

---Проверка структуры проекта
./run.sh structure
Команда выводит структуру файлов и директорий проекта, начиная с текущей папки.

---Очистка данных
./run.sh clear_data
Команда удаляет из папки data/ файлы:
*.csv
*.html

После очистки результаты работы программы удаляются. Повторный запуск команд
./run.sh run_generator
./run.sh run_reporter
снова создает
data/data.csv
data/report.html


---Проверка доступа контейнеров к данным
Проверка контейнера генератора
./run.sh inside_generator

Команда запускает контейнер генератора и показывает содержимое папки /data изнутри контейнера.Так можно убедиться, что контейнер видит локальную папку data/.

Проверка контейнера аналитика
./run.sh inside_reporter -Команда запускает контейнер аналитика и показывает содержимое папки /data изнутри контейнера.
Так можно убедиться, что контейнер видит файлы, созданные генератором.

# Полная последовательность запуска
Для полной проверки проекта можно выполнить:
./run.sh build_generator
./run.sh run_generator
./run.sh build_reporter
./run.sh run_reporter

После этого в папке data/ должны появиться:
data.csv
report.html

Проверить можно командой:
ls data

Ожидаемый результат:
data.csv  report.html

---Проверка HTML-отчета

После выполнения:
./run.sh run_reporter
нужно открыть файл:
data/report.html

В отчете должны отображаться:
общее количество строк;
таблица числовых колонок;
таблица частот для колонки destination.

---Проверка очистки и повторного создания данных
Команды:
./run.sh clear_data
ls data
удаляют CSV- и HTML-файлы из папки data/.

После этого данные и отчет можно пересоздать:
./run.sh run_generator
./run.sh run_reporter
ls data

Ожидаемый результат:
data.csv  report.html

Почему используется монтирование папки data/
Контейнеры Docker являются изолированными. Если контейнер создает файл только внутри себя, после завершения контейнера файл может быть недоступен на хосте.

Поэтому в проекте используется монтирование локальной папки:
data/
в папку контейнера:
/data
Генератор создает файл:
/data/data.csv
но благодаря монтированию этот файл появляется локально как:
data/data.csv

Аналитик читает этот же файл из /data/data.csv и создает:
/data/report.html
который появляется локально как
data/report.html

В run.sh учитывается запуск из Git Bash на Windows. Для корректного монтирования папки data/ используется определение пути проекта через pwd -W и переменная MSYS_NO_PATHCONV=1 . Это нужно, чтобы Git Bash не искажал путь, который передается в Docker. Я нашла это решение в статье-блоге когда вбила саму проблему. https://jasonsteinshouer.com/docker-path-issue-on-bash-for-windows вот ссылка на статью.
